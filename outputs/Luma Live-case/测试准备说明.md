# Luma Live 三端测试准备

本轮用例为静态设计，全部尚未执行。请在同一测试环境运行三个端；下述名称和金额是可准备的测试样本，不是新增业务规则。

## 账号与共同对象

| 测试对象 | 准备要求 |
| --- | --- |
| 普通用户 | 至少三个已登录可用账号，昵称海风、月光、星河；分别准备好友、非好友、拉黑及未拉黑关系 |
| 主播 | 至少两个完成公会初审及平台终审的账号，分别可开普通房、密码房及门票房；无权限、退会、封禁场景另建隔离账号 |
| 公会 | 晨星公会及另一对照公会；使用平台创建的公会长账号，准备仅管理一家及同时管理两家公会的账号 |
| 后台 | 有相应菜单与操作权限的管理员；系统账号、角色管理使用超级管理员；准备一个无相关权限的对照账号 |
| 运营账号 | 由所属公会创建；真实账号与运营账号分开，虚拟金币不混入真实余额 |
| 直播场次 | 每次开播记录唯一场次 ID，区分当前场次、上一场及再次开播的新场次 |
| 申请和订单 | 三端联调使用同一个申请 ID、用户 ID、主播 ID、公会 ID或订单 ID，不用相同昵称代替对象关联 |

## 可控条件

- 短信、邮箱和第三方登录使用测试渠道，记录发码时间、验证码、账号绑定关系和本次授权返回值。失败、取消、过期和重复回调须能单独控制。
- 金币用例执行前记录真实余额或虚拟余额；除本条事件外，禁止该样本账号出现其他收支。每条结束后使用另一独立样本或恢复测试环境数据。
- 幸运礼物确定性用例需要测试环境可指定本次独立开奖结果；不能只反复抽取并把随机命中当成验证完成。不能控制时将该条执行结果标为“阻塞”。
- 退款使用支付渠道沙箱或测试回调；分成使用财务确认的测试导入模板，先预览再确认，记录导入批次号。
- 时间边界、周期重置、月度额度使用统一测试时钟。业务时区、任务周起点及秒级截止未确认的分支保留在需求待确认，不擅自采用本机时区。
- 跨端影响由配合账号先完成触发，再由本条用例的执行角色在指定端观察。不要把公会或后台操作写成用户 App 中存在的按钮。

## 执行记录

Excel 的“测试结果”默认“未测”，按实际执行改为通过、不通过、阻塞或不适用，并填写测试人员。失败时在备注记录环境版本、对象 ID、实际结果及截图或日志位置；未执行不得标为通过。

三个工作簿的同一 Q 编号表示同一个产品决策，请统一填写结论。“流程编号”用于找同一业务流程的正常及异常分支，不能把同编号所有用例顺序执行成一条长流程。
