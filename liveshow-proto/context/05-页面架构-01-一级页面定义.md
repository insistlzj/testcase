# 页面架构 01 —— 一级页面定义（用户/主播 App）

> 依据：《01-角色与用例》（以最新版为准）、《03-业务对象清单》、《04-互动场景权限矩阵》、竞品分析（Mango Live / Dazz Live / Momo Live / Dream Live）
> 范围：本篇只定义一级页面（底部 Tab 框架层）；直播间页、会话页等二级页面及其状态矩阵在下一篇展开。
> 用例引用以名称为准。
> 2026-07-22 更新：首页定稿为"热门（关注头像栏+Banner+双栏）/ 新人（三栏）"两排序 Tab——关注 Tab 移除，由热门页顶部闪动描边头像栏承接（早期关注密度低，头像栏优于沉浸流）；Tab 框架定稿为"首页｜福利｜消息｜我的"四页，**无中央开播按钮**——开播入口收进"我的 · 主播中心"（早期供给由工会招募 + 平台审核驱动，不占底部一级入口）；榜单为首页重点二级入口；第七节决策全部关闭。

## 〇、一级框架总览

```
┌─────────────────────────────────────────────┐
│                （页面内容区）                  │
├───────────┬───────────┬───────────┬─────────┤
│   首页     │   福利     │   消息     │   我的   │
│  (广场)    │ (任务活动)  │   (IM)    │(个人中心)│
└───────────┴───────────┴───────────┴─────────┘
```

**四个一级页（首页｜福利｜消息｜我的，已定稿），无中央开播按钮**。框架级决策依据：

1. **第 4 页放"福利"而非第二内容形态（已定稿）**：竞品（Mango/Dazz/Momo/Dream）的第 4 个 Tab 普遍是第二内容支柱（1v1 视频聊 / 动态社区 / 语音房），其隐含前提是内容供给密度——那是"内容富余期"的答案。本产品处于发展早期，内容供给（主播量、场次）是最稀缺资产，第 4 页应服务早期三命题：拉新（邀请裂变是印尼市场验证的最低成本获客通道）、留存（内容不够厚时机制先顶上）、运营自由度（全后台配置、不发版持续更新的运营阵地）。**实现要求：建成低耦合的配置化容器**（内容区块后台驱动，核心区块可 H5 化）——二期供给成熟后此 Tab 让位于第二内容形态时，替换为配置动作而非重构。
2. **不设开播按钮，开播入口收进"我的 · 主播中心"（已定稿）**：早期主播供给由工会招募 + 平台审核驱动（B 端通道），不依赖 C 端转化漏斗，开播入口不占底部一级位。配套动线要求：**已认证主播在"我的"页顶部常驻"开始直播"快捷按钮**（仅主播身份可见），避免"我的→主播中心→开播"三级路径损伤主播的高频动线；普通用户的"成为主播"引导保留在主播中心入口的未认证态。

## 一、首页（直播广场）

**定位**：内容消费主入口，承载全部进房流量。

| 区块 | 内容 | 功能与规则 | 关联用例/口径 |
|---|---|---|---|
| 顶部栏 | 搜索入口（通栏） | 搜索跳搜索页（主播昵称/用户 ID/直播间，含搜索历史与热门词） | 搜索直播内容 |
| 双榜单入口（关注头像栏上方，横排双胶囊） | 左"主播榜"（收礼）、右"贡献榜"（送礼），各带 TOP3 上榜者头像叠 + 榜单图标，渐变底色区分（参考 Soul 双榜入口样式，2026-07-22 定稿） | 点击进入全局榜单页：日/周/月切换、K/M/B 缩写展示、头部前三大席位（头像大图 + 在播状态 + 一键进房）；发奖依据取榜单快照对象；粉丝榜为单主播维度、归属直播间与主播主页，不在全局榜 | 查看榜单 |
| 运营位 | Banner/活动位 | 后台配置素材、跳转与排期 | 运营位配置（后台） |
| 排序 Tab | **热门 / 新人** 两个（2026-07-22 定稿：关注 Tab 移除，由热门页顶部关注头像栏承接） | 见下三行 | 浏览直播广场 |
| 关注头像栏（热门 Tab 顶部，横滑） | 仅展示"已关注且在播"的主播头像，**闪动描边为直播态标识**；排序：已入团主播优先 → 最近开播 | 点击头像单房进入直播间（完整进房判定链，门票/密码房照常弹校验）；**无人在播时整栏隐藏**；与开播提醒推送互补（推送管 App 外、头像栏管 App 内）；完整关注列表管理入口在消息页与"我的" | 进入直播间；关注关系 |
| 热门 Tab（双栏 + Banner） | Banner 运营位（后台配置素材/排期，支持主播位直跳直播间，承担重点主播曝光）+ 双栏卡片流：封面、昵称/头像、标题、在线人数、分类标签、角标体系（热门角标权重后台配 / NEW 新人自动挂 / 已关注·已入团主播卡片描边高亮） | 下拉刷新、上拉加载；点击进房——普通房直进、门票房弹购票确认、密码房弹密码输入（口径 9⑭）；进房校验按 06 判定链 1；分类标签条过滤（后台配置） | 进入直播间；运营位配置 |
| 新人 Tab（三栏） | 三栏小卡：封面 + 昵称 + NEW 角标，信息最简、密度优先 | 使命为新主播冷启动广撒曝光；"新人"资格（开播 X 天内）后台可配 | 进入直播间 |
| 密码房入口 | 广场列表最下方 | 仅展示对当前用户可见的密码房 | 密码进入密码直播间 |
| 空状态 | 热门/新人：占位插画 + "去发现"引导；关注头像栏无人在播时整栏隐藏 | 无在播内容时展示 | — |

**页面级状态**：用户被拉黑的主播直播间在本页对其隐藏（口径 6④）。

## 二、消息（IM 与通知中枢）

**定位**：三个互动场景中"私信"与"粉丝群"的一级入口，通知触达集散地。

| 区块 | 内容 | 功能与规则 | 关联用例/口径 |
|---|---|---|---|
| 会话列表 | 私信会话（含主播直播间私信会话）、粉丝团群聊 | 私信为账号 ↔ 账号对等场景，统一公式校验：黑名单双向拦截 > 好友关系 > 双向发送；主播直播间私信与普通私信同列同样式，场次内回复即自动建好友（发送前提示），场次结束后未互通会话回复框禁发并引导申请好友 | 发送私信；回复直播间私信；口径 10 |
| 好友申请 | 收到的好友申请列表 | 通过/拒绝（账号基础能力，主播身份共用同一入口） | 处理好友申请 |
| 关系入口 | 好友列表、关注列表、粉丝列表 | 查看关系、发起会话（好友间）、删除好友（双向即时禁发，历史会话不提供授权——口径 10） | 管理社交关系；删除好友 |
| 通知中心 | 系统消息、互动通知（被关注/被送礼）、开播提醒、平台公告 | 开播提醒经站内通知+推送下发（不走 IM）；已读/未读 | 查看通知消息 |

**主播侧叠加**（同一页面，身份态差异）：粉丝团群聊内群主可对成员禁言/全员禁言（基础版，口径 9⑦）、群发消息、移出粉丝团成员（二次确认，矩阵场景二）；直播间私信的发起权在直播间场景，本页仅承载会话。

## 三、开播入口（位于"我的 · 主播中心"，非一级页）

**定位**：主播生产入口，按身份状态三态分流；已认证主播另有"我的"页顶部快捷开播按钮（总览决策 2）。

| 当前状态 | 进入页面 | 内容与功能 | 关联用例/口径 |
|---|---|---|---|
| 已认证且权限"已开通" | 开播准备页 | 标题/封面/分类标签、房型三选（普通 / 门票房设价 / 密码房设密码+可见名单+广场展示开关）、基础美颜、清晰度、摄像头预览 → 开始直播（触发粉丝开播提醒推送）；门票/密码房受后台灰度开关控制，且不支持连麦或 PK | 开始直播；口径 9⑭ |
| 未认证 / 审核中 / 被驳回 | 成为主播引导页 | 流程指引：加入工会 → 提交实名认证 → 等待审核；状态回显（审核中/驳回原因+重新提交） | 申请成为主播；提交/重新提交主播认证 |
| 权限"已关闭"或"被平台锁定" | 权限状态提示页 | 展示关闭/锁定原因；口径 9①：平台为总开关，平台关闭/锁定时工会不可开启 | 权限状态回显 |

开播后进入**直播间页（主播视角）**——与观众视角为同一页面的两种状态（"场景定身份"原则），详见下一篇二级页面。开播入口链路：我的 → 主播中心 → 开播准备；或"我的"页顶部快捷按钮直达开播准备（已认证主播）。

## 四、福利（任务·签到·邀请）

**定位**：促活与拉新的运营阵地，全部规则后台可配；架构上为**阶段性配置化容器**（见总览决策 1），二期可整体让位于第二内容形态。

| 区块 | 内容 | 功能与规则 | 关联用例/口径 |
|---|---|---|---|
| 每日签到 | 签到日历、连续天数、断签规则说明 | 领取金币/道具/经验，连续签到加成；道具入背包、金币入钱包 | 每日签到 |
| 任务中心 | 日常/成长任务列表（观看、关注、送礼、分享） | 进度展示、完成后领取奖励 | 领取任务奖励 |
| 邀请拉新 | 我的邀请码（分享外部社交）、拉新数据（绑定人数、每人返利明细、累计获赠） | 返利状态展示冻结/驳回及申诉结果（口径 9④）；绑定关系一次性不可改 | 分享邀请码；查看拉新数据 |
| 运营位 | 新人首充礼包等活动位 | 后台排期 | 充值金币（引流） |

## 五、我的（个人中心）

**定位**：资产、身份、关系与设置的聚合页；主播能力区按身份态条件展示。

| 区块 | 内容 | 功能与规则 | 关联用例/口径 |
|---|---|---|---|
| 资料卡 | 头像、昵称、用户 ID、财富等级标识 | 编辑资料（头像/昵称提交后台审核）；财富等级图标后台配置 | 编辑个人资料 |
| 钱包 | 金币余额、充值入口、账单 | iOS IAP / Android+H5 三方支付；充值记录、消费记录、收支明细；未支付订单可取消、超时自动取消（口径 9⑬） | 充值金币；取消充值订单；查询账单 |
| 背包与装扮 | 背包（已获得道具：头像框/气泡/勋章等，含有效期）、等级与勋章展示 | 背包查看与穿戴管理；多类标识按位展示（财富等级与粉丝团勋章分位） | 管理背包与装扮 |
| 我的工会 | 已入会：工会信息/成员/公告、退会申请；未入会：工会列表（推荐 5 个+搜索）与入会申请 | 同一时间仅可加入一个工会；退会需工会长审批 | 浏览工会；申请加入/退出工会 |
| 我的粉丝团 | 已加入的粉丝团列表（粉丝团等级 / 我的粉丝等级 / 我的亲密度） | 查看粉丝团等级、我的粉丝等级与亲密度；主动退团或被主播移出后，仅我的粉丝等级和亲密度前台清零、重入不恢复 | 查看粉丝团与关系成长；退出粉丝团 |
| 主播中心（条件展示） | 认证入口/状态 → 认证通过后展开：收益（收益层数字，口径 9⑨）、收益明细、提现（申请/进度，不可撤回、不限次额——口径 9⑩⑪）、结算记录、数据中心（本场/历史数据）、粉丝团管理、直播间黑名单管理（两层独立解除） | 提现链路：线上工单→后台审核→财务线下打款（口径 1） | 主播侧全部查询与提现用例 |
| 黑名单管理 | 已拉黑账号列表 | 解除拉黑（按分层规则恢复权限与可见性） | 管理账号黑名单 |
| 设置与合规 | 账号安全、通知开关、隐私、语言（英语/马来西亚语/印尼语）、账号注销（冷静期+资产校验）、退出登录；客服/帮助/意见反馈；封禁申诉入口 | 注销前校验未提现收益/未消费金币 | 编辑设置；注销账号；提交申诉/反馈 |

## 六、一级页面外的全局层（不占 Tab，此处仅登记）

- **直播间页**（观众/主播双态同页）——App 核心页面，观众从首页/开播提醒进入，主播从"我的 · 主播中心"开播进入；
- **登录/注册流程页**（第三方/手机/邮箱、协议勾选）——前置于框架；
- **搜索页、榜单页、主播个人主页、用户资料卡（半浮层）、举报流程页**——由各 Tab 二级进入；
- **H5 充值页**——App 外独立（印尼盾计价、支付倒计时、客服入口）。

## 七、框架决策记录（已全部定稿）

1. 第 4 页＝福利（任务·签到·邀请·活动），依据见总览决策 1；工会入口归"我的"。
2. 不设中央开播按钮；开播入口收进"我的 · 主播中心"（三态分流保留），已认证主播配"我的"页顶部快捷开播按钮。
3. 榜单为首页顶部二级入口——主播榜 + 贡献榜承担平台"热闹"氛围展示；粉丝榜归单主播维度（直播间/主播主页）。
4. 关注 Tab 移除，由热门页顶部"关注头像栏"（闪动描边=在播，横滑，空则整栏隐藏）承接——早期人均关注数与开播率低，沉浸流滑两下到底、头像栏三个头像也不显空，且省去首页直播流预加载的实现成本；二期关注密度上来后可升级独立关注 Tab，头像栏保留为常驻提醒。
5. 待拍板遗留：直播间内上下滑切换房间（范围＝关注在播列表）一期是否实现——建议一期不做、纯单房进出，滑动切房列二期增强。
