## 1. admin-dashboard.html
### 场景
平台管理员查看最新经营指标、近 7 日趋势、被动退款和快捷入口。
### 字段
| 字段 | 规则 |
| --- | --- |
| 活跃用户 / 新增用户 | 最新自然日打开 App（启动或从后台切回前台）的去重登录用户数 / 完成注册的去重用户数。 |
| 总充值金额 / 人数 | 支付成功充值订单的实付金额合计 / 去重用户数。 |
| 新用户充值金额 | 最新自然日注册用户当日支付成功的充值金额合计。 |
| 新用户 ARPU | 新用户充值金额 / 新用户充值人数；分母为 0 时记 0。 |
| 达成有效天主播 | 最新自然日累计有效直播不少于 3 小时的去重主播数。 |
| 被动退款 | 支付渠道发起的退款记录，按退款时间倒序。 |
### 业务
1. 指标卡取最新自然日，趋势取截至该日最近 7 个自然日。
### 交互
1. 点击指标卡 -> 切换趋势；刷新 -> 重新取数；点击退款记录或快捷入口 -> 进入对应页面。

## 2. admin-user-list.html
### 场景
平台管理员查询用户并查看详情、封禁或解封。
### 字段
| 字段 | 规则 |
| --- | --- |
| 用户信息 | 头像、昵称和全局唯一用户 ID。 |
| 账号状态 | 仅正常、封禁。 |
| 财富等级 | 当前等级；筛选上下限为非负整数且上限不得小于下限。 |
| 累计充值 | 支付成功充值订单实付金额合计。 |
| 累计消费 | 普通、定制、门票扣减金币 + 幸运礼物扣减金币 - 幸运礼物返奖；失败、撤销和虚拟金币不计。 |
| 金币余额 | 当前真实金币余额；充值退款可使其为负。 |
| 所属公会 | 当前有效关系，无公会显示“-”。 |
| 注册时间 | 首次注册时间；时间筛选首尾均包含。 |
### 业务
1. 封禁后立即下线，正在直播时同时关播，未登录账号禁止登录。
### 交互
1. 查询 -> 条件取交集；导出 -> 当前筛选结果。
2. 封禁或解封 -> 填写原因并确认 -> 更新并留痕。

## 3. admin-user-detail.html
### 场景
平台管理员核对单个用户的资料、资产、设备、关系和违规记录。
### 字段
| 字段 | 规则 |
| --- | --- |
| 基础资料 | 用户 ID、昵称、手机号、地区、注册时间和账号状态取当前值。 |
| 金币余额 | 当前真实金币余额；负数时禁止消费。 |
| 充值流水 | 充值订单、基础金币、赠送金币、渠道和状态。 |
| 消费流水 | 商品、数量、扣减金币、主播和直播场次，只读。 |
| 登录设备 | 设备、系统、应用版本、最近登录时间和状态。 |
| 关注 / 粉丝 | 当前有效关系。 |
| 违规记录 | 举报或审核来源、结论、处置和时间。 |
### 业务
1. 解封只恢复登录，不自动恢复直播权限。
2. 充值退款扣回原订单全部到账金币，但不撤销已完成消费。
### 交互
1. 切换 Tab -> 加载明细；账号处置 -> 填写原因并确认 -> 更新并留痕。

## 4. admin-host-list.html
### 场景
平台管理员查询主播并管理账号、直播权限和公会管理权限。
### 字段
| 字段 | 规则 |
| --- | --- |
| 主播 / 公会 | 主播身份来自认证通过；公会为当前有效关系。 |
| 账号状态 | 仅正常、封禁，独立于直播权限。 |
| 开播权限 | 最终权限 = 账号可用且公会有效且认证通过且平台开启且公会开启。 |
| 金币收益 | 普通、定制和门票按实际消费；幸运礼物按礼物价值 × 配置比例；虚拟金币不计。 |
| 违规次数 | 已确认违规记录数，不含不成立或已作废。 |
### 业务
1. 平台关闭直播权限时立即关播并禁止再次开播。
2. 锁定期间公会设置跟随平台且不可改；解锁后恢复锁定前设置并重算权限。
### 交互
1. 变更权限、警告、封禁或解封 -> 填写原因并确认 -> 记录前后值、操作人和时间；导出当前筛选结果。

### 业务
1. 封禁账号与关闭直播权限独立；解封不恢复直播权限。
### 交互
1. 切换 Tab -> 加载记录；权限或账号处置 -> 填写原因并确认 -> 更新并留痕。

| 字段 | 规则 |

1. 状态、主播和公会筛选取交集；详情 -> 核验材料并处理。

## 8. admin-live-management.html
### 场景
平台管理员查询直播中和已结束场次并巡查或处置。
### 字段
| 字段 | 规则 |
| --- | --- |
| 直播场次 ID | 每次开播唯一；主播直播间 ID 长期不变。 |
| 房型 | 普通、密码、门票，取开播时快照。 |

1. 结束后保留消息、消费、处置和收益，历史场次不可重开。
### 交互
1. 查询 -> 条件取交集；警告 -> 直播继续；关播 -> 立即结束当前场次。

## 9. admin-live-detail.html
### 场景
平台管理员查看单场直播画面、场次数据和巡房记录并即时处置。
### 字段
| 字段 | 规则 |
| --- | --- |
| 场次信息 | 场次 ID、主播、房型、标题和时间取本场快照。 |
| 观众人数 | 本场进入直播间的去重用户数。 |

## 10. admin-inspection-schedule.html
### 场景
平台管理员查询、启停巡房排班并查看排班人员。
### 字段
| 字段 | 规则 |
| --- | --- |
| 排班编号 | 创建时生成，全局唯一。 |
| 日期 / 时间段 | 平台统一时区；结束时间晚于开始时间。 |
| 排班人数 | 有效巡房人员数量。 |
| 状态 | 待生效、生效中、已停用、已结束；按时间和启停状态计算。 |
### 业务
1. 仅有效排班或任务期间赋予巡房会话身份；可进入任意直播间，无需密码或门票。
2. 巡房会话不受主播黑名单和本场踢出限制，主播与房管不可对其拉黑或踢出。
3. 保护仅限巡房会话，原有拉黑关系不变；平台封禁或巡房权限失效仍不可进入。
### 交互
1. 停用 -> 不再生效；重新启用 -> 按当前时间重算状态。

## 20. admin-guild-list.html
### 场景
平台管理员查询、新建、启停或解散公会。

| 字段 | 规则 |

### 交互

## 25. admin-lucky-gift-config.html
### 场景
平台管理员查询、上下架和维护幸运礼物开奖配置。
### 字段
| 字段 | 规则 |
| --- | --- |
| 幸运礼物收益比例 | 全部幸运礼物共用；默认 1%，可配置 0% 至 100%。 |
| 单次消耗 | 每次独立开奖先扣减的正整数金币。 |
| 开奖次数 | 单笔礼物包含的独立开奖次数，正整数。 |
| 单价 | 单次消耗 × 开奖次数。 |
| RTP | Σ（奖励金币 × 中奖概率）/ 单次消耗 × 100%；按概率配置实时计算，结果超过一位小数时向上取整至一位小数。 |
| 状态 | 单礼物上下架；功能总开关关闭时全部幸运礼物不可见。 |
### 业务
1. 每次开奖独立；单次期望返还 = Σ（奖励金币 × 中奖概率），用户实际消费 = 礼物价值 - 实际返还。
2. 返还金币进入用户余额；主播收益 = 幸运礼物价值 × 赠送时收益比例，默认 1%，返还结果不影响主播收益。
3. 收益记录保存赠送时的比例快照，修改比例不重算历史收益。
4. 下架不影响已完成开奖、消费和结算记录。
### 交互
1. 点击编辑 -> 比例可输入、按钮变为保存；保存 -> 校验 0% 至 100% -> 对保存后的新赠送生效。
2. 礼物编辑 -> 进入配置详情；上下架或删除 -> 确认后执行。

## 41. admin-level-config.html
### 字段与数据归属
| Tab | 统计对象 | 配置字段 |
| --- | --- | --- |
| 主播等级 | 单个主播累计获得的收益。 | 等级、收益数值（金币）、勋章图。 |
| 财富等级 | 单个用户向所有主播累计送礼的贡献。 | 等级、送礼贡献（金币）、勋章图。 |
| 粉丝等级 | 单个用户对单个主播的送礼贡献，不同主播分别计算。 | 等级、对主播送礼贡献（金币）、勋章图。 |
| 粉丝团等级 | 单个粉丝团累计收礼。 | 等级、粉丝团累计收礼（金币）、勋章图。 |
### 业务规则
1. 四类等级独立配置、独立计算；同一账号可同时具有主播等级、财富等级及面向不同主播的粉丝等级。粉丝团等级属于粉丝团，不等同于成员的粉丝等级。
2. 四类等级默认均为 1 级，1 级门槛固定为 0；每行配置一个等级对应的金币门槛及勋章图，此处配置不直接增加收益、送礼贡献或钱包金币。
3. 已有粉丝团规则：用户退出或被移出后，粉丝等级与亲密度清零；主播的粉丝团解散后，成员团籍和群聊权限解除。粉丝等级统计需遵循该重置规则，不能直接用永久历史送礼总额恢复。
4. 主播等级的收益按分成前金币收益计入。
5. 已有门槛修改并保存后，立即按新配置重算对应类型的已有等级；等级编号由系统生成，不提供手动修改。
6. 填写的金币数值为达到该等级所需的累计门槛；累计值大于或等于门槛即达标，同时满足多档时取最高等级，允许一次跨越多级。
7. 运营账号的虚拟金币不计入主播等级收益、财富等级送礼贡献、粉丝等级对主播送礼贡献或粉丝团等级累计收礼。
### 配置校验与操作
1. 等级为从 1 开始连续递增的固定数字，不可编辑；四个 Tab 各自独立编号。1 级金币数值固定为 0 且不可修改；2 级及以上必填，并且必须大于上一级，否则禁止保存并定位到错误等级。
2. 每次新增等级，当前 Tab 的等级编号自动加 1，金币数值留空待填写；当前页不提供删除入口。
3. 切换 Tab 保留各自未保存的输入和图片。保存只校验并提交当前 Tab；无效数值或缺少勋章图均阻止保存，成功后留在当前 Tab。
### 勋章图
1. 每个等级单独上传或更换图片，选择可读取的图片后显示预览；预览不改变图片比例。勋章图必填，缺少图片时提示对应等级并阻止保存。
2. 取消选择保留原图片；非图片或损坏图片提示重新选择，保留原有有效图片。上传及更换仅影响对应 Tab 的对应等级。
3. 勋章图在客户端的展示位置、是否随等级自动替换及是否允许手动佩戴，需与装扮规则确认后实施。
### 保存边界（待确认）
1. 建议保存整组配置时全部成功或全部失败；失败保留输入供重试，重复提交不新增重复档位；多人同时编辑时提示配置已变更，避免覆盖他人修改。原型尚未模拟服务端保存失败或并发编辑。
### 其他待确认边界
1. 普通、定制、幸运礼物的计入范围；粉丝团收礼的归属条件；金币小数精度与数值上限。
2. 统计数据延迟时何时更新等级。
3. 勋章图修改后的客户端刷新时机；重算后历史记录使用旧等级还是新等级。
4. 勋章图允许的格式、大小和尺寸；无可用图片时的客户端展示方式。
### 原型范围
编辑、图片预览和保存反馈仅在当前页面模拟；刷新后恢复 Mock 数据，不实际上传、持久化或触发用户等级变化。以上待确认方案未作为正式计算逻辑实现。

| 字段 | 计算方式 |
| --- | --- |
| 发放金币 | 本次公会发放的正整数虚拟金币。 |
| 发放后余额 | 发放前余额 + 发放金币。 |
| 操作人 | 实际执行发放的公会账号。 |
| 发放时间 | 发放成功时间，计入对应自然月额度。 |
### 业务
1. 虚拟金币只能由所属公会发放，不能通过充值或任务获得；平台不执行发放。
2. 运营账号没有真实金币，虚拟金币与真实金币隔离且不可转换。
### 交互
1. 查询 -> 公会、账号和时间取交集。

## 81. admin-operation-gift-records.html
### 场景
平台管理员只读查询运营账号虚拟金币送礼记录。
### 字段
| 字段 | 计算方式 |
| --- | --- |
| 礼物 / 主播 | 赠送时普通或定制礼物及接收主播快照。 |
| 消费金币 | 礼物单价 × 赠送数量，从虚拟金币账户扣减。 |
| 赠送时间 | 成功扣减和送礼完成时间。 |
### 业务
1. 虚拟金币仅可用于赠送普通礼物和定制礼物，不能赠送幸运礼物，不能购买装扮、门票或用于其他消费。
2. 运营账号贡献值始终为 0，不进入任何榜单或排行；虚拟送礼仅计入公屏消息和礼物效果，不计入真实消费、主播收益或分成；页面中的幸运礼物示例不符合当前规则。
### 交互
1. 查询 -> 公会、账号和时间取交集；详情 -> 查看完整快照。

## 82. admin-operation-guild-controls.html
### 场景
平台管理员配置公会运营账号的月度虚拟金币额度。
### 字段
| 字段 | 计算方式 |
| --- | --- |
| 单账号月度额度 | 单个运营账号自然月累计可获虚拟金币上限。 |
| 公会月度额度 | 公会全部运营账号自然月累计发放上限。 |
| 本月累计已发放 | Σ 本月该公会成功发放金币。 |
| 账户余额累计 | Σ 该公会全部运营账号当前虚拟金币余额。 |
| 本月累计消费 | Σ 本月虚拟金币成功送礼消费。 |
| 本月剩余额度 | max（公会月度额度 - 本月累计已发放，0）。 |
### 业务
1. 额度只控制所属公会向运营账号发放的虚拟金币；运营账号不能通过充值或任务获得金币。
2. 公会总上限不得低于本月已发放；单账号上限不得低于本月单账号最高已发放，且不得高于公会总上限。
### 交互
1. 配置额度 -> 校验边界 -> 保存后限制公会后续发放。
