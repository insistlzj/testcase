# 用户App-直播模块：生成机制修复与覆盖复核

本轮交付 252 条测试用例和 4 项需求待确认。保留上版 214 条用例，新增 38 条；其中 6 条原用例只合并了来源、规则和场景追溯，前置条件、步骤和预期均未改变。

这次修复了已复现的解析、角色识别、来源合并和覆盖误判问题，但尚未完成全部业务条款及页面行为的语义建模。因此，本报告不能作为“原先三类缺口已经全部解决”或“直播模块已全覆盖”的证明。

## 问题、原因和修改位置

| 原问题 | 已确认原因 | 本轮修改 |
| --- | --- | --- |
| 原文大量未建模，部分错误生成场景 | 表格列被拆成孤立值；引用文案中的“及时”误作条件；并列动作可能丢失主语 | `scripts/evidence-discovery.mjs` 保留表头、整行决策条件和原始上下文，保护引号内文字，修正共享主语；没有完整解释的约束继续标为生成待复核 |
| 只能识别有限的业务表达 | 原生成器只有少量规则运算类型的用例设计器 | `scripts/scenario-design.mjs` 补充长度、容量、配置组合、处置状态、选择保存/取消、时间限制、数据筛选等设计；参数从当前来源读取，无最低用例数 |
| 看起来已测试，却无法获得覆盖证明 | 完全依赖原句匹配；“切换至新人”和“切换新人”、“页面显示”和“模拟弹窗”无法对应 | 同一模块内做有限的等价表达归一化；仍核对角色、页面、条件、动作、输入值和预期，不删除否定词及数值 |
| 合并后仍有已设计场景未覆盖 | 合并了相同设计，却未把另一条规则的直接来源带入用例 | 合并追溯后重新执行覆盖验证；同一来源文件只输出一条，并保留相关位置 |
| 页面控件解析错误 | 正则没有处理合法的换行结束标签，导致“热门”和“新人”合成一个按钮 | `scripts/parse-prototype-html.py` 使用标准库 HTML 解析器；动态模板与静态节点分别登记 |
| 元素挂错虚拟页面 | 同一物理文件按多个虚拟视图重复解析，后一次覆盖前一次 | `scripts/liveshow-evidence.mjs` 每个物理文件只解析一次，同时读取两组原型视图定义；物理页面、关联视图、容器及状态分别保存 |
| 查看主播资料卡被当作主播执行 | 文件名中包含 `host` 就被判为主播 | 按物理页面及当前查看视角确定执行角色；观众查看主播资料卡仍为观众 |
| 格式通过被误当作覆盖完成 | 来源存在、编号可对应，并不足以证明条件和结果被验证 | `scripts/validate-discovery.mjs` 重提取证据、重演规则和场景，验证实际用例条件及有符号断言；拒绝无依据的不适用、错挂元素、错误统计及删除缺口台账 |

入口仍为 `scripts/build-live-discovery.mjs`。两项共享输入/交付校验器接入 Schema 3.1；用例 JSON 字段和工作簿结构保持原契约。

## 仍需产品决定的四项

1. 当前有效房管列表的排序依据。
2. 可见粉丝选择列表的排序依据。

这四项有具体问题、可选方案和当前依据，已写入工作簿“需求待确认”。生成器自身的解析、设计、映射缺口保存在 `coverage-review-backlog.json`，不混入上述产品决定。
